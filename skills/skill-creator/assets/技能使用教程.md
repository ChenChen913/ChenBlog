# 技能使用教程

本教程指导您如何使用 skill-creator 技能来创建和管理 Claude 技能。

## 快速开始

### 什么是技能？

技能是扩展 Claude 能力的模块化工具包。它们包含：
- **专业工作流程**：特定任务的多步骤操作指南
- **工具集成**：处理特定文件格式或 API 的方法
- **领域知识**：公司特定信息、数据架构、业务逻辑
- **可重用资源**：脚本、参考文档、模板文件

### 何时创建新技能？

当您发现以下情况时，考虑创建技能：

1. **重复性任务**：您经常让 Claude 执行相同类型的工作
2. **专业领域**：需要特定知识或流程的任务（如财务分析、代码审查）
3. **工具使用**：需要使用特定工具或 API 的场景
4. **标准化需求**：需要保持输出格式或质量标准一致

## 创建技能的完整流程

### 阶段 1：规划

#### 1.1 明确需求
在创建技能前，先思考：

```
- 这个技能解决什么问题？
- 用户会如何触发这个技能？
- 需要支持哪些具体功能？
- 有哪些边界情况需要考虑？
```

#### 1.2 识别可重用组件
分析任务，确定需要哪些资源：

**脚本 (scripts/)**
- 用于需要确定性可靠性的代码
- 示例：PDF 旋转、数据转换、API 调用

**参考资料 (references/)**
- 用于需要反复查阅的信息
- 示例：数据库架构、API 文档、业务规则

**资产 (assets/)**
- 用于输出的模板或资源文件
- 示例：HTML 模板、品牌图标、文档模板

### 阶段 2：初始化

#### 2.1 运行初始化脚本
```bash
scripts/init_skill.py <技能名称> --path <输出目录>
```

#### 2.2 生成的结构
```
技能名称/
├── SKILL.md              # 主要说明文件
├── scripts/              # 可执行脚本
│   └── example.py        # 示例脚本
├── references/           # 参考文档
│   └── example.md        # 示例参考
└── assets/               # 资源文件
    └── example.txt       # 示例资产
```

### 阶段 3：编写 SKILL.md

#### 3.1 Frontmatter 部分
```yaml
---
name: 技能名称
description: |
  清晰描述技能的功能和触发条件。
  包括：做什么、何时使用、具体触发场景。
license: 完整条款见 LICENSE.txt
---
```

**描述写作要点：**
- ✅ 包含功能和触发条件
- ✅ 列出具体使用场景
- ❌ 不要在正文中写"何时使用"部分

#### 3.2 正文部分

**核心原则：**
1. **简洁为王**：只包含 Claude 需要的信息
2. **使用祈使词**："提取文本"而不是"你应该提取文本"
3. **分层组织**：基本信息在 SKILL.md，详细内容在参考文件

**推荐结构：**
```markdown
# 技能名称

## 快速开始
[基本使用方法]

## 核心功能
[主要功能说明]

## 高级功能
[详细功能，链接到参考文件]

## 参考资料
- [详细指南](references/guide.md)
- [API 文档](references/api.md)
- [示例集](references/examples.md)
```

### 阶段 5：打包和分发

#### 5.1 验证技能
```bash
scripts/package_skill.py <技能目录路径>
```

脚本会检查：
- ✅ YAML frontmatter 格式正确
- ✅ 必需字段存在
- ✅ 目录结构合理
- ✅ 文件组织正确

#### 5.2 生成 .skill 文件
验证通过后，生成 `技能名称.skill` 文件（实际是 zip 文件）。

#### 5.3 使用技能
将 `.skill` 文件分享给用户，用户可以：
1. 在 Claude 中加载技能
2. 根据描述自动触发
3. 按照说明使用

## 最佳实践

### 设计原则

#### 1. 渐进式披露
```
元数据 (100词) → SKILL.md (5k词) → 参考文件 (无限)
```

#### 2. 自由度匹配
- **高自由度**：文本说明，适用于灵活任务
- **中等自由度**：带参数的脚本，适用于有模式的任务
- **低自由度**：特定脚本，适用于精确任务

#### 3. 避免重复
- 详细信息放参考文件
- SKILL.md 只保留核心流程
- 不创建额外文档（README、CHANGELOG 等）

### 常见模式

#### 模式 A：多框架支持
```
技能/
├── SKILL.md (选择框架)
└── references/
    ├── framework-a.md
    ├── framework-b.md
    └── framework-c.md
```

#### 模式 B：领域分离
```
技能/
├── SKILL.md (导航)
└── references/
    ├── finance.md
    ├── sales.md
    └── product.md
```

#### 模式 C：功能分级
```markdown
## 基础功能
[简单说明]

## 高级功能
详细指南见 [ADVANCED.md](references/advanced.md)
```

### 质量检查清单

在打包前，检查：

- [ ] SKILL.md 描述是否清晰触发条件？
- [ ] 是否只包含必要信息？
- [ ] 脚本是否经过测试？
- [ ] 参考文件是否按需加载？
- [ ] 是否避免了冗余文档？
- [ ] 是否使用了正确的语言风格？

## 迭代改进

### 收集反馈
使用技能后，关注：
- 哪些步骤不清楚？
- 缺少哪些功能？
- 性能瓶颈在哪里？

### 更新流程
1. 识别问题
2. 更新 SKILL.md 或资源
3. 重新打包
4. 测试验证
5. 发布新版本

## 故障排除

### 常见问题

**Q: 技能没有触发**
- 检查 description 中的触发条件是否清晰
- 确认技能已正确加载

**Q: 输出质量不稳定**
- 增加具体示例
- 添加约束条件
- 使用参考文件提供详细指导

**Q: 上下文不足**
- 检查 SKILL.md 是否过于冗长
- 将详细内容移至参考文件
- 确保只加载必要的信息

## 进阶技巧

### 1. 条件逻辑
在 SKILL.md 中使用条件判断：
```markdown
如果用户要求 X：
- 执行步骤 A
- 参考 [X 指南](references/x.md)

如果用户要求 Y：
- 执行步骤 B
- 参考 [Y 指南](references/y.md)
```

### 2. 搜索模式
对于大型参考文件，添加搜索提示：
```markdown
当需要数据库信息时，在 references/schema.md 中搜索：
- "用户表" 或 "users"
- "订单表" 或 "orders"
```

### 3. 脚本参数化
使脚本更灵活：
```bash
scripts/process.py --input file.pdf --output result.pdf --format json --verbose
```

## 总结

创建有效技能的关键：
1. **理解需求**：明确使用场景
2. **合理规划**：识别可重用组件
3. **保持简洁**：只包含必要信息
4. **分层组织**：使用参考文件管理细节
5. **持续迭代**：基于反馈改进

通过遵循这些指导，您可以创建出既实用又高效的 Claude 技能。
