# Knowledge Distiller - 知识榨取器 Skill 介绍

> 文档版本：1.0
> 最后更新：2026-03-18

---

## 📌 概述

**Knowledge Distiller（知识榨取器）** 是一个结构化的知识提取工具，通过苏格拉底式的持续追问，帮助用户将脑中模糊的隐性知识说清楚、整理好、存下来。

它的核心定位不是"回答问题"，而是"提出好问题"——通过专业的采访技巧，挖掘用户内心深处那些"只可意会不可言传"的经验、判断和方法论。

---

## 🎯 核心价值

### 解决什么问题？

1. **隐性知识难以表达**：很多经验、直觉、判断标准存在于大脑中，但无法清晰地表达出来
2. **知识碎片化**：想法零散、不成体系，难以形成可复用的方法论
3. **认知盲区不自知**：不知道自己不知道什么，缺乏系统的自我审视
4. **经验难以传承**：个人 expertise 无法有效记录和传递给他人

### 带来什么价值？

- ✅ 将模糊直觉转化为清晰的方法论
- ✅ 将碎片想法整理为结构化笔记
- ✅ 暴露认知边界，明确学习方向
- ✅ 建立个人知识档案，支持长期追踪

## 🔧 核心功能

### 1. 四种对话模式

| 模式 | 适用场景 | AI 角色 | 目标 |
|------|---------|--------|------|
| **苏格拉底追问** | 有明确结论但逻辑不清 | 无知的求知者 | 挖掘隐性判断标准，澄清核心定义 |
| **质疑者对抗** | 观点片面或缺乏论据 | 挑剔的反对者 | 强化逻辑链条，补充事实论据 |
| **场景还原** | 讲述操作方法/经验 | 情境设定者 | 将抽象方法论落地为可执行 SOP |
| **自由漫谈** | 没有明确主题，寻找灵感 | 敏锐的倾听者 | 从碎片想法中捕捉有价值的洞察 |

### 2. 十大核心规则

1. **单点追问**：每次只问一个最关键的问题
2. **先承接后追问**：先确认理解，再抛出新问题
3. **定期整理**：每 5 轮对话进行阶段性整理
4. **"说清楚"优先**：温和指出错误，主动补充不完整视角
5. **记录偏差**：错误观点和不完整表述同样具有记录价值
6. **拒绝空泛**：追问具体案例，避免抽象空谈
7. **破冰引导**：引导用户从感触最深的事情开始
8. **生成笔记**：严格按照模板输出结构化笔记
9. **更新领域档案**：对话结束后自动更新领域档案
10. **随时查档**：支持查询未解决问题的盲区

### 3. 启动流程

```
1. 档案检查 → 检查是否有历史领域档案
                    ↓
2. 模式选择 → 展示四种对话模式供用户选择
                    ↓
3. 主题确认 → 询问"今天最想说清楚的是什么"
                    ↓
4. 正式追问 → 开始苏格拉底式对话
```

- **已解决存档**：历史问题的解决记录

## 🎓 使用场景

### 适合的场景

| 场景 | 典型问题 |
|------|---------|
| **经验总结** | "我做这个项目学到了很多，但说不清楚具体是什么" |
| **方法论梳理** | "我知道怎么做，但不知道如何教给别人" |
| **决策复盘** | "当时做了这个决定，但背后的逻辑没理清楚" |
| **认知探索** | "对这个领域有兴趣，但不知道自己的认知边界在哪" |
| **写作准备** | "想写篇文章，但思路很乱" |
| **学习反思** | "学了很多东西，但感觉不成体系" |

### 不适合的场景

- ❌ 需要快速获取事实性答案
- ❌ 需要技术指导或代码调试
- ❌ 需要创意生成或头脑风暴（虽然可以用自由漫谈模式，但效率不高）
- ❌ 需要情感安慰或心理疏导

### 场景：用户想梳理"如何做产品决策"的方法论

```
用户：我想梳理一下我做产品决策时的思路

AI：好的，在开始之前，我想先了解一下——你希望用哪种方式进行这次对话？

【展示四种模式】

用户：苏格拉底追问吧

AI：好的。那么，你今天最想说清楚的，是什么样的判断或感受？

AI：有趣。能举个最近发生的具体例子吗？你在什么情况下做了一个产品决策？

用户：上周我们讨论要不要加一个新功能...

AI：（追问）你说"要不要加"，最终的决定是什么？为什么？

AI：（阶段性整理）根据我们刚才的讨论，你做产品决策时主要考虑三点：
1. ...
2. ...
3. ...
是这样吗？需要补充或修正吗？

...（对话继续）

用户：今天就到这里吧，帮我整理一下

AI：（生成完整的隐性知识萃取笔记）
```

## 🔍 特色功能详解

### 1. 认知纠偏记录

这是 Knowledge Distiller 的独特功能——不仅记录"正确的知识"，也记录"从错误到正确的过程"。

**示例**：
```markdown
### 纠偏记录 1
- **原始说法**：Gateway 和 Agent 是一个东西
- **问题所在**：混淆了两个独立进程的概念
- **纠正后**：Gateway 和 Agent 是两个独立进程，通过 RPC 通信
- **来源**：AI 主动纠正
```

这个功能的价值在于：
- 记录认知升级的轨迹
- 避免未来犯同样的错误
- 形成"对比学习"的材料

### 2. 领域档案长期追踪

支持跨对话的知识积累：

```markdown
## 领域档案：AI Agent / OpenClaw

### 最近更新日期：2026-03-12
### 状态：LEARNING

### 已掌握
- [x] Gateway 的四大核心功能 _(from 2026-03-12)_
- [x] Session 隔离机制 _(from 2026-03-12)_

### 模糊区域
- [ ] MCP 和 Skill 的具体开发流程 _(from 2026-03-12)_

### 待深挖问题
- [ ] 如何实现跨平台身份链接？ _(from 2026-03-12)_
```

### 3. 可延伸写作方向

每次对话结束后，AI 会主动提出"基于这次对话，未来可以写什么文章"：

```markdown
## 6. 可延伸写作的方向

- [ ] 主题 A：《从"养孩子"到"养龙虾"：AI 时代的养成乐趣》
- [ ] 主题 B：《普通人如何用 AI 集合多个公众人物的智慧？》
- [ ] 主题 C：《"现代版李白"：跨时空人格实验的可能性》
```

这个功能的价值：
- 将对话成果转化为可传播的内容
- 提供写作灵感
- 形成个人 IP 的素材库

## 🚀 最佳实践建议

### 1. 对话前准备

- ✅ 明确你想探索的领域（如"产品决策"、"团队管理"、"技术架构"）
- ✅ 准备 1-2 个具体案例或情境
- ✅ 预留足够的时间（建议 30 分钟以上）

### 2. 对话中配合

- ✅ 诚实回答，不要"装懂"
- ✅ 尽量用具体案例而非抽象描述
- ✅ 被 AI 质疑时，不要防御，而是思考"为什么我会这么想"
- ✅ 如果问题太抽象，可以要求 AI"换个问法"

### 3. 对话后复盘

- ✅ 仔细阅读生成的笔记
- ✅ 标记"答不上来的问题"，制定学习计划
- ✅ 关注"可延伸写作方向"，选择 1-2 个深入
- ✅ 定期回看领域档案，追踪认知升级

## 📈 进阶用法

### 1. 多轮对话深挖

针对同一个领域，进行多次对话：

```
第 1 次：自由漫谈 → 发现核心主题
第 2 次：苏格拉底追问 → 澄清核心概念
第 3 次：质疑者对抗 → 强化逻辑链条
第 4 次：场景还原 → 落地为 SOP
```

### 2. 跨领域对比

建立多个领域档案后，可以进行跨领域对比：

- "我在产品决策和技术决策时的判断标准有什么异同？"
- "团队管理和自我管理的底层逻辑是否相通？"

### 3. 定期复盘

建议每月进行一次领域档案复盘：

- 哪些模糊区域已经清晰了？
- 哪些盲区已经探索过了？
- 哪些待深挖问题已经解决了？
- 新的认知边界在哪里？

## 📚 与其他技能的区别

| 技能 | 核心功能 | 与 Knowledge Distiller 的区别 |
|------|---------|---------------------------|
| **learning-assistant** | 学习技术概念、准备面试 | 以"教"为主，提供知识讲解 |
| **voice-diary** | 口述日记记录 | 以"记录"为主，不主动追问 |
| **brainstorming** | 创意发散 | 以"发散"为主，不追求深度 |
| **knowledge-distiller** | 隐性知识提取 | 以"追问"为主，追求深度和清晰度 |

**核心差异**：
> Knowledge Distiller 不追求"给你答案"，而是追求"让你说清楚"

- 🎯 **不是单次对话**，而是**长期追踪**

它的核心价值在于：
> **帮助你把那些"只可意会不可言传"的隐性知识，变成可以清晰表达、可以传承、可以迭代的结构化知识。**

如果你有以下需求：
- 想把经验变成方法论
- 想把直觉变成逻辑
