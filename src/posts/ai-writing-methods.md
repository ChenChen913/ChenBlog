凌晨两点,盯着空白的文档,大脑一片空白。

公众号写作这条路上,80% 的人都倒在了「不知道怎么开始」这一步。但好消息是,在 AI 时代,这个问题解决起来比以往任何时候都简单。

今天这篇文章,我会把 **「三种借助 AI 高效完成公众号写作的方法」** 全部告诉你。不管你是零基础小白,还是想提升效率的老手,都能找到适合自己的解题思路。

## 方法一：自己造一套工作流，打造专属「写作外挂」（Prompt 深度使用）

这是最苦、但也最能打出差异化的一条路。

为什么？因为自己打磨出来的东西,最懂你的风格，也最贴合你的需求。

> 你可能会问：既然方法二可以直接创建 Skill，为什么还要自己折腾 Prompt？
>
> 答案是：**「市面上火的 Skill 本质就是提示词，只是被封装得更「高级」一点」**。你套用的 Skill 和自己写的 Prompt 其实是一回事——只是别人的 Prompt 经过包装，你看不见逻辑。
>
> 直接套用别人的 Skill，你并不知道里面封装了什么，用起来容易「水土不服」。而方法一的意义在于：当你一步步设计 Prompt、反复调试、优化时，你在完成系统性的「写作思维训练」——内容框架、方向、风格、需求……这些问题想清楚，文章自然写得好。

### 第一步：和 AI 一起搞清楚基本问题

动笔之前，我们需要先搞清楚几个根本性问题。这些问题不是你自己想，而是要和 AI 一起探讨：

**「写什么类型？」** 测评？教程？观点？故事？不同类型的文章，写法天差地别，AI 会结合你的想法帮你分析哪种类型更适合你的定位。

**「用什么形式？」** 纯文字？还是图文并茂？这里有个关键点：公众号单张图片的文字信息建议控制在 1000 字以内，但正文不设上限。所以如果你想做图文字，图片承载的是「视觉信息」，文字才是「核心输出」。AI 会帮你规划图文搭配的节奏。

**「你的目标读者是谁？」** 小白用户需要通俗易懂，同行则可以直接上专业术语。告诉 AI 你的读者画像，它会帮你调整表达方式。

把这些信息告诉 AI，让它帮你梳理清楚。后面的工作会顺畅很多。

**【可直接复制的提示词】**

```
我想写一篇公众号文章,但目前想法还比较模糊。
我的初步想法是：【这里用户只需要写一句话或几个关键词，比如「关于AI写作」或「如何提升工作效率」】
请你设计 5-8 个追问问题,帮助我把想法澄清得更具体。
每个问题要针对一个关键维度（文章类型、内容形式、目标读者、写作目标等）。
追问维度参考:
1. 文章类型：想写什么类型的文章？（比如测评类：对比分析多个产品；教程类：教读者一步一步做某件事；观点类：表达某个独特见解；故事类：讲述一个经历或案例）
2. 内容形式：是纯文字，还是图文并茂？（公众号单张图片的文字信息建议控制在1000字以内，图片承载视觉信息，文字是核心输出）
3. 目标读者：谁会看这篇文章？（比如：刚入门的小白、有一定经验的从业者、想解决问题的普通用户）
4. 写作目标：希望读者看完有什么收获？（比如：学会某个技能、了解某个概念、获得某个观点的认同）
请每个问题都附带 1-2 个具体示例,帮助我理解并回答。
格式示例:
Q1：关于文章类型，您想写的是？（示例：比如「测评类：对比XX和XX哪个更好」或「教程类：教大家如何从零开始做XX」）
```

### 第二步：让 AI 去调研，别闭门造车

你以为的「独特选题」，可能早就有人写过了。

这不可怕，可怕的是你不知道别人已经写到什么程度了。

调研的方式有很多种，关键是让 AI 用对工具、去对地方：

**「方式一：开启 AI 的深度研究模式」**

现在的 AI 大多支持「深度搜索」或「研究模式」——比如 ChatGPT 的 Search 功能、Claude 的 Web Search、DeepSeek 的联网搜索等。

你可以这样告诉 AI:

我想调研【XX话题】相关的公众号文章,请开启深度搜索模式,找出 10 篇这个领域的代表性文章,分析它们的选题角度、内容深度、写作风格。

调研时请注意:

1. 优先搜索最近 6 个月内的文章(公众号内容更新迭代快)
2. 关注阅读量较高的文章(说明是用户真正关心的)
3. 关注评论区的讨论(那是用户的真实痛点和需求)

**「方式二：用搜索型 AI 辅助调研」**

Perplexity、纳米搜索这类搜索型 AI，擅长在全网范围内快速抓取和整理信息。

你可以让它帮你:

- 快速了解这个话题在各个平台的热度
- 找出这个话题的核心争议和讨论点
- 发现你可能没想到的角度

**「方式三：多平台交叉调研」**

同一个话题，在不同平台的热度和讨论角度可能完全不同：

| 平台 | 调研重点 |
| --- | --- |
| 公众号/微信搜索 | 深度长文、爆款规律、读者评论 |
| 知乎 | 深度分析、专业视角、高赞回答 |
| 小红书 | 用户痛点、真实体验、热门话题 |
| 微博/推特 | 热点讨论、舆论风向、话题标签 |
| Reddit | 国外用户的真实讨论、深度社区讨论 |
| Youtube | 视频内容的角度和切入点 |

调研完后，AI 会给你一份报告，如果发现已经有人在做了——这其实是好事，说明这个方向有市场，AI 会帮你分析他们的不足，找到你可以切入的差异化角度。

如果发现几乎没有同类内容——这时候反而要小心，AI 会和你一起思考：为什么没有人写？是市场太小，还是难度太大？

**【可直接复制的提示词】**

```
基于我之前的初步想法,我想写一篇关于【XX话题】的公众号文章。
请按以下步骤进行市场调研:
【调研方式】
1. 开启你的深度搜索模式,优先搜索最近 6 个月内的内容
2. 重点调研以下平台(按优先级排序):
   - 公众号/微信搜索(深度长文、爆款规律、读者评论)
   - 知乎(深度分析、专业视角、高赞回答)
   - 小红书(用户痛点、真实体验、热门话题)
   - 微博/推特(热点讨论、舆论风向)
3. 如果条件允许,也可以搜索 reddit、youtube 等平台,获取更多视角
【调研要求】
1. 找出 5-10 篇这个领域的代表性文章,分析它们的:
   - 选题角度(他们都在写什么角度)
   - 内容深度(是浅层介绍还是深度分析)
   - 写作风格(口语化还是专业化)
   - 爆款特征(开头方式、结构模式、金句设计)
2. 总结这些文章的共同点
3. 找出差异化空间(还有哪些角度没人写过但值得写)
【输出要求】
1. 先给我一份调研报告,列出找到的文章和关键发现
2. 基于调研结果,问我 3-5 个确认问题,每个问题附带参考答案
格式示例:
Q1:这个领域目前已经有不少文章,您觉得自己的文章能有什么独特角度?(参考答案:比如"我可以结合自己的亲身经历"或"我可以聚焦在一个更细分的小众领域")
Q2:(根据调研发现的某个点,继续追问用户偏好)
```

### 第三步：和 AI 来一场「深度对话」

这是整个流程中最核心的环节。

调研完后，把你了解到的信息告诉 AI，然后**「让 AI 来「追问」你」**：

「你到底想表达/突出什么观点?」

「这篇文章最想让读者记住哪一句话?」

「你的风格是严肃还是轻松?」

「有没有你特别想避开的表达方式?」

这个追问的过程，本质上是在帮你把模糊的想法「具象化」。

AI 会根据你的回答，给出一个初步的框架。如果你觉得哪里不对，直接说；如果你觉得缺了什么，也让 AI 补上。这个环节可能会来来回回好几次，直到你俩达成共识。

别嫌麻烦。框架打磨得越细,后面写起来越顺。

**【可直接复制的提示词】**

```
经过前面的调研和讨论,我对自己的写作方向已经有了一定了解。
现在请你设计一套系统性的追问问题,帮助我把文章框架打磨清楚。
追问维度包括:
1. 核心观点:您这篇文章最想表达的一个核心观点是什么?(参考答案:比如"AI不会取代人类,但会使用AI的人会取代不会用的人")
2. 记忆点:您最想让读者记住的一句话是什么?(参考答案:比如"与其担心被AI取代,不如先学会用AI")
3. 写作风格:您希望文章读起来是什么感觉?(参考答案示例:轻松幽默像朋友聊天 / 严谨专业像专家分享 / 犀利尖锐像批评反思)
4. 避坑提醒:有没有您特别想避开的表达方式?(参考答案:比如不想太说教、不想太长篇大论、不想用太多专业术语)
5. 结构偏好:您希望文章整体用什么结构?(参考答案示例:
   - 总分总:开头提出观点,中间分点论述,结尾总结升华
   - 问题-分析-解决:先抛出问题,再分析原因,最后给出解决方案
   - 起承转合:像讲故事一样有情节起伏)
请一个问题一个问题地问,我们来来回回讨论,直到达成共识。每个问题都请给出您的参考答案示例。
```

### 第四步：AI 自我审核，至少改三遍

文章初稿完成后，AI 会进行至少三轮自我审核：

第一遍：**「语言风格与格式检查」**。AI 会检查是否存在机械、套路、生硬的表达,把那些「太像 AI 说的话」全部改掉，让文字有「人味」。同时检查公众号特有的格式限制（如引用块字符数不超过300字），避免发布后才发现内容被截断。

第二遍：**「改病句」**。AI 会检查有没有读起来卡顿的地方、重复啰嗦的地方、逻辑跳跃的地方,一一修正。

第三遍：**「核实内容」**。AI 会核实文章里提到的数据、案例、观点是否真实可靠。公众号文章最怕的就是「造谣一张嘴,辟谣跑断腿」。

**【可直接复制的提示词（第一遍/语言风格与格式检查）】**

```
请对以下文章进行两个方面的检查：
【第一部分：语言风格检查】
找出所有「太像 AI 说的话」(机械、套路、生硬的表达),然后改掉它们。
判断标准:
1. 机械套路:比如"首先、其次、最后"连用三次以上,或者"众所周知"、"不言而喻"等万能短语
2. 过长句子:一口气读完很累,需要喘气的长句
3. 空洞表达:说了像没说一样的车轱辘话
4. 过度连接:堆砌"此外"、"另外"、"与此同时"等连接词
修改要求:
1. 用口语化、个性化的表达替换机械表达
2. 把长句拆成短句,读起来更轻松
3. 保留核心观点和内容不变
4. 改完后标注出改了哪些地方(用【】标注)
【第二部分：公众号格式检查】
检查文章中的所有引用块(用 > 标记的内容)是否符合公众号格式要求:
1. 字符数检查:逐个检查每个引用块的字符数(不含 > 符号和空格)
2. 超限提示:如果某引用块超过 300 字符,请标注:
   - 【超限】第X个引用块共XXX字符,超出XX字符
   - 给出缩减建议:如何精简表达、拆分成多个引用块、或改为正文
3. 其他公众号格式问题:
   - 引用块内是否有代码块(可能导致显示异常)
   - 引用块内是否有复杂格式(建议简化)
格式示例:
【超限】第1个引用块共328字符,超出28字符
建议:删除冗余表达"目前市面上比较火的那些"改为"市面上火的",或拆分成两个引用块
修改前后请用对比格式呈现。
```

**【可直接复制的提示词（第二遍/改病句）】**

```
请检查以下文章是否有以下问题,有则修正:
1. 读起来卡顿的地方(换种说法会更顺)
2. 重复啰嗦的地方(删掉重复的内容)
3. 逻辑跳跃的地方(补充缺失的过渡)
4. 标点符号问题:
   - 中英文标点混用(比如:中文文章用了英文逗号, 而非中文逗号,)
   - 标点使用不当(比如:句号当逗号用、滥用感叹号等)
   - 引号使用不规范(中文文章应用中文引号「」或『』,而非英文引号"")
5. 中英文数字和首尾空格问题:
   - 英文数字和中文文字之间缺少空格(比如:GPT4.0 应为 GPT 4.0)
   - 中文文字和英文数字之间缺少空格(比如:苹果14天 应为 苹果 14 天)
   - 数字首尾有多余空格
6. 其他格式问题(段落缩进不统一、列表格式不一致等)
请标注出每个问题所在的位置,并给出修改后的版本。
```

**【可直接复制的提示词（第三遍/核实内容）】**

```
请核实以下文章中的信息是否真实可靠:
1. 数据和统计:文中提到的数字、数据是否准确?来源是否可靠?
2. 案例真实性:文中引用的案例、故事是否真实存在?如有虚构成分请指出
3. 观点依据:文中的观点结论是否有依据支撑?是否过于主观?
4. 事实核查:是否有夸大、误导性、与事实不符的表述?
如果发现问题,请用以下格式标注:
- 【存疑】原文:XXX,建议:XXX
并给出修改建议。
```

### 第五步：AI 标注配图位置，人机协作完成配图

文字和图片是相互成就的。

AI 会在文章里标注「这里需要配图」，并把这些图片需求分为两类：

**「你必须提供的图。」** AI 会标注出来哪些图必须由你自己提供，比如教程类的操作截图、测评类的产品实拍、对比类的数据图表——这些只有你自己有，AI 生成不了。

**「AI 生成的图。」** 当某些内容比较抽象、或者读起来有点干的时候，AI 会建议「此处可配一张氛围图」，并且给出这张图的提示词描述。你可以用 AI 生图工具来实现。

好图片的标准是：能帮你把「说不清楚的东西」说清楚，或者能调节文章的阅读节奏，让读者喘口气。

**【可直接复制的提示词】**

```
请阅读以下文章,标注出需要配图的位置,并将图片需求分为两类:
【第一类:必须用户提供的图】
请标注:需要用户提供什么图?用来说明什么内容?
格式示例:
- 【用户提供】第3段需要一张XX截图,用于说明XX操作步骤
- 【用户提供】第5段需要一张产品实拍图,用于展示XX的外观
【第二类:AI 生成的氛围图】
请标注:需要什么氛围的图?并给出详细的图片生成提示词
格式示例:
- 【AI生成】第2段需要一个XX氛围图
  提示词:XXX(详细描述画面内容、风格、色调)
配图原则:
1. 用户提供的图:必须是用户自己有的(截图、照片、数据图表等)
2. AI 生成的图:用于调节阅读节奏、增强视觉表达
3. 不要为了配图而配图,每张图都要有存在的意义
```

## 方法二：让 AI 直接给你一套方案（Skill 的创建）

如果你觉得「自己造轮子」太慢、太累,那就试试这条更直接的路径。

**「核心思路：让 AI 生成一个「写作助手 Skill」。」**

你可以这样告诉 AI（其实就是方法一的简化版）：

**【简化版提示词】**

```
「我想做一个公众号辅助写作的 Skill。用户给出选题后,AI 负责调研、和用户多轮商讨、确定写作方案;方案确定后开始撰写,撰写完成后进行至少三次自我审核;审核通过后,AI 在文章中标注需要配图的地方,有些图需要用户自己提供(如截图),有些图则以提示词形式占位。我希望这个 Skill 不只是机械执行,而是能根据我的需求灵活调整。你觉得你需要了解什么信息,才能给我一份完整的 Skill 创建方案?」
```

这套方法的好处是：你只需要「提需求」，AI 负责「搭框架」。

如果你觉得提示词需要更完整，我把方法一的整体流程抽象为一个完整的提示词：

**【完整版提示词】**

```
我想创建一个「公众号文章写作助手」Skill,用于帮助用户从选题到成稿完成一篇公众号文章。
这个 Skill 的核心工作流程如下：
**第1步：和用户一起搞清楚基本问题**
- 要求：用户只需要给出一句话或几个关键词的初步想法（比如"关于AI写作"或"如何提升工作效率"）
- AI 设计 5-8 个追问问题,帮助用户澄清想法
- 追问维度包括：文章类型（测评/教程/观点/故事）、内容形式（纯文字/图文）、目标读者、写作目标
- 每个问题必须附带 1-2 个具体示例,帮助用户理解并回答
**第2步：让 AI 去市场调研**
- AI 搜索并分析 5-10 篇同类文章,分析选题角度、内容风格、写作结构
- 总结这些文章的共同点(开头方式、结构模式、表达风格)
- 找出差异化空间(哪些角度没人写过但值得写)
- 基于调研结果,问用户 3-5 个确认问题,每个问题必须附带参考答案
- 示例：Q1：这个领域已有不少文章，您觉得自己的独特角度是什么？（参考答案：比如"结合自己的亲身经历"）
**第3步：与用户深度对话（核心环节）**
- AI 设计一套系统性的追问问题,必须一个问题一个问题地问
- 追问维度包括：
  - 核心观点：最想表达的一个核心观点是什么？（附参考答案示例）
  - 记忆点：最想让读者记住的一句话是什么？（附参考答案示例）
  - 写作风格：希望读起来是什么感觉？（示例：轻松幽默像朋友聊天 / 严谨专业像专家分享）
  - 避坑提醒：特别想避开的表达方式？（示例：不想太说教、不想太长篇大论）
  - 结构偏好：整体用什么结构？（示例：总分总 / 问题-分析-解决 / 起承转合）
- 来来回回讨论,直到用户确认框架达成共识
**第4步：AI 撰写与自我审核（必须严格执行）**
- 根据确认的框架撰写文章初稿
- AI 进行至少三轮自我审核：
  1. 语言风格与格式检查：删除机械套路表达（如"首先/其次/最后"连用、过度连接词），把长句拆短；检查引用块字符数不超过300字，避免被截断
  2. 改病句：检查卡顿、重复、逻辑跳跃，重点检查标点符号（中英文混用、引号规范）、中英文数字空格
  3. 核实内容：数据统计是否准确、案例是否真实、观点是否有依据、是否有夸大误导
- 审核不通过则返回修改,通过后进入下一步
**第5步：AI 标注配图位置**
- AI 在文章中标注需要配图的位置，分为两类：
  - 【用户提供】：必须用户自己有的图（教程截图、产品实拍、数据图表），说明用于什么内容
  - 【AI生成】：氛围图，给出详细的图片生成提示词（画面内容、风格、色调）
**核心原则**
- 多设计追问问题,少让用户自己填表
- 所有问题都要附带参考答案示例,降低用户回答门槛
- 审核流程必须严格执行三轮,不能跳过任何一轮
- 配图标注要清晰区分用户图和 AI 生成图
```

而且创建这个 Skill 不一定非要在 CLI 里完成。你可以在网页端和 AI 直接对话,也可以用 Coze2.0之类的平台——工具是为人服务的,选最顺手的就行。

## 方法三：站在巨人的肩膀上成长（进阶）

这是最务实、也最高效的一条路。

先简单回顾一下我在方法一和方法二中提到的策略：

**「方法一的思路」**：和 AI 深度协作，每一步都让 AI 追问、确认、调研，最后让 AI 完成写作、三轮审核、配图标注。这是一条「自己搭框架」的路。

**「方法二的思路」**：把方法一的流程固化成 Skill，让 AI 直接生成一个自动化工具，你只需要提需求、做决策、审结果。这是一条「让 AI 搭框架」的路。

这两个方法的核心是：**「让 AI 帮你做执行层面的事」**。

### 3.1 花叔的方案：两层判断 + 个人素材库

花叔文章链接：[Claude Code是最好的自动化写作Agent，附完整教程！](https://mp.weixin.qq.com/s?__biz=Mzg2OTA1OTAxNA==&mid=2247487055&idx=1&sn=5afd08915bada3cf9995a329bf618345&scene=21#wechat_redirect)

**「花叔的方案,比我多了几个关键点——这也是他更「高级」的地方。」**

#### 3.1.1 两层判断机制

我方法一是一个线性的 5 步流程（澄清问题 → 调研 → 深度对话 → 写作审核 → 配图），但花叔的方案多了一个「工作区判断」层（公众号/视频/Prompt梳理），然后才是「任务类型判断」（有 brief 的新任务/无 brief 的新任务/修改文章/审校/咨询）。

这里提到了 **「brief（需求简报）」**：就是用一张纸把写作需求说清楚，包括写作目标、目标读者、核心观点、约束条件、必须包含的内容、禁止出现的内容。有 brief，AI 就知道边界在哪里，不会跑偏。

这两层判断意味着：AI 不会「瞎猜」。它知道自己在哪个场景、该走哪套流程。流程可预测，协作才高效。

#### 3.1.2 个人素材库：事前预防而非事后补救

我方法一中提到的降 AI 味，是让 AI 在审核环节「删套话、拆长句」。这是**「事后补救」**。

但花叔的思路是**「事前预防」**：写作前就让 AI 从个人素材库中提取真实素材（他用 Grep 在即刻动态中搜索关键词），用真实经历、观点、案例替代编造。

**「受他启发，我也在搭建分层素材库：」**

- **「第一层」**：自己的写作风格（写作习惯、用词偏好、句式特征、金句风格）——这是「根」
- **「第二层」**：国内头部博主或者某些官方媒体号的风格（学他们怎么抓开头、设计结构、调动情绪）
- **「第三层」**：国外顶尖博主（Dan Koe、Justin Welsh 等，学他们怎么用简单词说深刻道理）

核心是：**「你的真实素材，远比 AI 的润色技巧更能消除 AI 味」**。

#### 3.1.3 三遍审校：顺序不同，第二轮更系统

对比一下：

| 轮次 | 我的版本 | 花叔的版本 | 对比 |
| --- | --- | --- | --- |
| 第一轮 | 语言风格与格式检查（删套话、拆长句、检查引用块字符） | 内容审校（事实、逻辑、结构） | 侧重点不同：我的偏语言层面（怎么写得不像 AI），他的偏内容层面（怎么保证内容对） |
| 第二轮 | 改病句（卡顿、重复、标点、空格） | 风格审校（删套话、拆句式、口语化、加细节） | 他的更系统，把「怎么让文章更好读」拆成了 6 个具体动作，还给了改写示例（比如「在当今AI技术飞速发展的时代...」→「Claude Code出了。我用了两周，确实比Cursor好用。」） |
| 第三轮 | 核实内容（数据、案例、观点） | 细节打磨（句子、段落、标点、节奏） | 侧重点不同：我的偏「真实性」（别写假东西），他的偏「可读性」（读起来爽） |

**「建议」**：新手用花叔的版本（更系统），有经验的可以混合使用。但不管用谁的版本，**「三轮审核不能跳过」**。

#### 3.1.4 透明化思考：每次决策都说明过程

我在方法一中提到了「AI 追问」这个环节，但花叔更进一步——他要求 AI **「每次做决策时都说明思考过程」**，比如「我认为这个标题可以从 X 和 Y 两个角度考虑...」「对比了三种方案后，我觉得方案 A 更适合，因为...」。

好处是：你可以看到 AI 的思考过程，及时纠正方向。不只是让 AI 帮你干活，而是让 AI 教你干活。

#### 3.1.5 可复制 vs 不可复制

**「你可以直接复用这些「工具」，但「核心」需要自己积累。」**

**「可复制的部分」**（直接拿去用）：

- 两层判断机制（任何领域都适用）
- Brief 需求简报（让 AI 不瞎猜）
- Think Aloud 透明化（每次决策说明思考过程）
- 三遍审校机制（降 AI 味）

**「不可复制的部分」**（需要你自己积累）：

- 个人素材库（你的真实经历、观点、案例）
- 风格特征（每个人的风格不同）
- 行业知识（你自己的专业经验）

**「关键是」**：两层判断、三遍审校这些只是「工具」——让你用 AI 更高效。但你的真实经历、观点、风格，这些才是「核心」——让读者觉得「这就是你写的」。

### 3.2 宝玉的方案：从「创作者」升级成「导演」

宝玉文章链接：[朋友想复刻我的 AI 写作流程，但用不了 Claude Code，结果我帮他找到了替代产品](https://mp.weixin.qq.com/s?__biz=Mzk1NzgxMjQ0OA==&mid=2247492385&idx=1&sn=a14c4c7a944dd90090a97ac23fdaa9eb&scene=21#wechat_redirect)

如果花叔是在「优化协作流程」，那宝玉的核心理念是：**「从「内容创作者」升级成「内容导演」」**。

导演做什么？选剧本、定调性、把控最终效果。但导演不会自己扛摄像机，不会自己打灯，不会自己剪片子——这些事情交给专业团队。

宝玉的工作流也是这样：**「选题自己定，核心观点自己想，最终呈现效果自己把关——但具体的执行环节，全部交给 AI Agent。」**

这个「导演思维」落地到具体操作上，就是**「模块化工作流」**。

#### 3.2.1 什么是模块化工作流

我方法二创建的 Skill，是把整个写作流程（调研、写作、审校、配图）全部集成在一个 Skill 里。这就像一把瑞士军刀，什么都能干，但不够专精。

但宝玉的做法是：**「把每个环节拆成独立的 Skill」**，有专门分析素材的、专门写大纲的、专门润色的、专门配图的、专门发布的……每个 Skill 只做一件事，但把它做到极致。

**「这样做的好处是什么？」**

第一，**「每个 Skill 更专注、更高效」**。AI 在执行单个任务时，提示词更清晰，出错率更低。比如配图 Skill 只需要关注"怎么根据内容生成合适的图"，不用管其他环节。

第二，**「灵活组合，按需调用」**。今天只想润色一篇文章？直接调用润色 Skill。明天想生成几个配图？调用配图 Skill。不需要走完整流程。

第三，**「迭代优化更容易」**。发现配图效果不好？只需要改配图 Skill，不用动整个流程。发现润色不够到位？只优化润色 Skill 就行。

#### 3.2.2 值得借鉴的三个细节

**「① 素材搜集自动化」**

我在方法一中的素材调研，是「按需搜索」——有需求了再让 AI 去搜。

但宝玉设置了一个定时任务，让 AI 每天自动在网上搜集相关资讯，整理成简报。**「这不光是为了写作，更是为了自己每天获取信息更方便」**。早上起来，简报已经躺在那里，挑有兴趣的深挖就行。

这个思路可复用：如果你也是某个领域的重度信息消费者，可以设置定时任务，让 AI 每天帮你整理行业资讯、技术动态、竞品动向……把"刷信息"这个动作自动化。

**「② 风格学习的迭代思维」**

花叔的做法是：写作前从个人素材库中搜索真实经历、观点，用真实素材替代编造。

但宝玉创建了一个「风格 Skill」，把自己过往的文章上传，让 AI 学习用词习惯、句式结构、表达方式。**「而且这个风格是不断迭代的」**——每次 AI 写完，他手动修改，然后让 AI 看他改了哪些地方、为什么这么改，下次就会写得更像。

这意味着：不是用真实素材替代编造，而是让 AI 在一次次迭代中越来越懂你的风格。

**「③ 机械性问题用脚本解决」**

润色环节，我都是让 AI 全包（删套话、改病句、标点空格）。

但宝玉的做法是：AI 负责内容层面（语法、拼写、句子结构），脚本负责格式层面（中英文空格、标点符号全角半角）。一键运行，格式全部统一。

这种"AI + 脚本"的组合很实用：AI 做需要判断的事，脚本做机械的事，各司其职。

#### 3.2.3 宝玉 vs 花叔：两种不同的「高级」

| 对比维度 | 花叔的方案 | 宝玉的方案 |
| --- | --- | --- |
| 核心理念 | 优化协作流程（两层判断、透明化思考） | 模块化工作流（每个环节独立 Skill） |
| 流程组织 | 一个完整流程，从头走到尾 | 多个独立 Skill，灵活组合 |
| 素材来源 | 写作前从个人素材库搜索真实素材 | 定时任务自动搜集（方便自己每天获取信息） |
| 风格学习 | 用真实素材替代编造（事前预防） | 创建风格 Skill，迭代学习（越来越像你） |
| 润色环节 | 三遍审校（内容/风格/细节） | 脚本处理格式 + AI 处理内容 |
| 适用场景 | 希望深度参与每个环节，在协作中学会写作 | 希望最大化效率，把每个环节做到极致 |

两种方案都很好，但思路不同：

- **「花叔的方案」**：适合希望在协作中学习写作的人。AI 是你的助手，也是你的老师。
- **「宝玉的方案」**：适合希望把每个环节打磨到极致的人。模块化让你可以不断优化单个 Skill，效率越来越高。

但共同点是：**「选题自己定，观点自己想，最终效果自己把关——但具体的执行，交给 AI。」**

## 彩蛋：我的实战工具链——Obsidian + Claudian + NoteToMP

前面讲了三种方法，最后给你看看我自己是怎么做的。

我的工作流很简单：**「在 Obsidian 里写作，用 Claude 协助创作（通过方法二创建的 Skill），最后一键发布到公众号草稿箱。」**

整个流程不需要切软件，不需要复制粘贴，不需要二次排版。

### 4.1 三个工具分别是什么？

**「Obsidian」**：本地 Markdown 笔记软件，用于知识管理和内容沉淀。你的文章、素材、想法全部存在这里，数据完全在自己手里。

**「Claudian」**：一个 Obsidian 插件，让你在 Obsidian 里直接调用 Claude。就这么简单——它不是什么神奇工具，只是把 Claude 网页版「搬」到了 Obsidian 里。

**「NoteToMP」**：一个 Obsidian 插件，一键把 Markdown 文章发布到公众号草稿箱，自动转换格式、上传图片。

### 4.2 为什么是这三个工具？

**「不用 Claudian 的时候」**：你在 Claude 网页版写文章，它不知道你过去写过什么、不知道你积累了哪些素材、不知道你的写作风格。每次都要从头介绍背景，效率很低。

**「用了 Claudian 之后」**：Claude 可以「看到」你的 Obsidian 笔记库。你可以让它搜索你过去的文章、调取你积累的素材、学习你的写作风格。更重要的是——你可以直接在 Obsidian 里调用你在方法二中创建的「公众号写作助手」Skill。

**「NoteToMP 解决的是发布问题」**：传统做法需要复制到在线排版工具、调整格式、复制 HTML、粘贴到公众号后台、手动上传图片……整个过程至少半小时。NoteToMP 一键搞定，10 秒发布。

### 4.3 实战：在 Obsidian 里用 Skill 写公众号

还记得方法二中创建的「公众号写作助手」Skill 吗？有了 Claudian，你可以在 Obsidian 里直接调用它。

**「第一步：在 Obsidian 里新建笔记」**

新建一个 Markdown 文件，比如「如何用 AI 写公众号.md」。

**「第二步：打开 Claudian，调用 Skill」**

在 Obsidian 里打开 Claudian 插件，直接告诉它：

```
请调用「公众号写作助手」Skill,我想写一篇关于【AI 写作】的文章。
```

Claude 会开始执行 Skill 里定义的流程：

- 设计追问问题，帮你澄清想法
- 进行市场调研
- 多轮对话打磨框架
- 撰写初稿
- 三轮自我审核
- 标注配图位置

**「关键区别在于」**：现在 Claude 可以「看到」你的笔记库了。它可以在调研时搜索你过去写的相关文章，可以在写框架时参考你的素材库，可以在审核时对比你的写作风格。

**「第三步：写完后，一键发布」**

文章写完了，在 Obsidian 里按 Ctrl+P（或 Cmd+P），输入「NoteToMP：发布到公众号草稿箱」，回车。

10 秒后，打开公众号后台，文章已经在草稿箱里了。预览一下，没问题就可以直接发布。

### 4.4 这套工具链的核心价值

**「相比 Claude 网页版」**：Claude 懂你的知识库，不用每次从头介绍背景。

**「相比其他写作工具」**：Obsidian 是你的知识库，素材可沉淀、可复用、可连接。

**「相比传统排版工具」**：NoteToMP 一键发布，不需要复制粘贴、不需要二次排版。

**「更重要的是」**：这三个工具的组合，让「写作」这件事从「一次性消耗」变成了「持续积累」。你写的每一篇文章、积累的每一个素材，都会成为下一篇文章的养料。

## 写在最后

三条路，适合不同阶段的人：想深度打磨的选方法一，想快速上手的选方法二，有标杆可学的选方法三。**「但更重要的是理解背后的思维。」**

花叔的「两层判断机制」「三遍审校流程」，宝玉的「模块化工作流」「迭代学习思维」，这些不只是写作方法论——更是一套可复用的 AI 协作框架。你可以把它迁移到代码编写、项目构建、产品开发等任何需要 AI 辅助的场景。

核心就三点：**「把复杂任务拆解成标准化流程，把你的专业知识和风格沉淀成可复用的 Skill，让 AI 做执行、你做决策。」**

写作也好，编程也好，想一百遍不如动手做一遍。从今天开始，选一个适合你的方法，动起来。
