# 文章字体放大与排版微调计划

## Summary
本次计划的目标是：在保留当前“文章正文/标题使用霞鹜文楷 CDN、导航与侧边栏保持无衬线字体”的前提下，将文章阅读字号整体放大一号，并确保标题层级、正文节奏、列表/引用/公式的观感同步协调。

## Current State Analysis
- 当前文楷字体方案已经接入，入口位于 [index.html](file:///c:/Users/11853/Desktop/个人网站/blog/index.html#L42-L48)，通过 `LXGW WenKai Screen` CDN 提供文章阅读字体。
- 文章字体族定义在 [index.css](file:///c:/Users/11853/Desktop/个人网站/blog/src/index.css#L3-L19) 的 `--font-kai`，并已应用到 `.article-body`、正文标题、段落、列表、引用等元素。
- 文章正文当前没有显式 `font-size`，见 [index.css](file:///c:/Users/11853/Desktop/个人网站/blog/src/index.css#L175-L190)；因此正文主要继承默认字号，导致在文楷字体下观感偏小。
- 文章页主标题字号写在 [Post.tsx](file:///c:/Users/11853/Desktop/个人网站/blog/src/pages/Post.tsx#L397-L399)，当前为 `text-xl md:text-3xl`。
- 正文内 h2/h3 目前存在双重字号来源：
  - CSS 强制样式：见 [index.css](file:///c:/Users/11853/Desktop/个人网站/blog/src/index.css#L67-L98)
  - `ReactMarkdown` 渲染器 inline style：见 [Post.tsx](file:///c:/Users/11853/Desktop/个人网站/blog/src/pages/Post.tsx#L532-L569)
  因此任何字号调整都必须同步修改两处，否则会出现“改了但没完全生效”的问题。
- 当前测试文章已经放入实际生效目录 [src/posts](file:///c:/Users/11853/Desktop/个人网站/blog/src/posts)，说明后续验证可直接基于真实文章页完成，不需要再依赖独立测试页。

## Proposed Changes
### 1. 调整文章正文基础字号
- 文件：[index.css](file:///c:/Users/11853/Desktop/个人网站/blog/src/index.css)
- 修改位置：`.article-body` 及 `.article-body p / li / blockquote / th / td` 相关样式区域。
- 计划做法：
  - 为 `.article-body` 增加统一的基础字号与更适合文楷的行高。
  - 让 `p`、`li`、`blockquote`、表格文本随正文同步增大，避免只放大段落导致其他文本显小。
- 目标效果：整篇文章的阅读体验整体放大一号，但不会影响导航、目录、时间信息等 UI 区域。

### 2. 同步放大正文内标题层级
- 文件：[index.css](file:///c:/Users/11853/Desktop/个人网站/blog/src/index.css)
- 文件：[Post.tsx](file:///c:/Users/11853/Desktop/个人网站/blog/src/pages/Post.tsx)
- 修改位置：
  - CSS 中 `.article-body h2`、`.article-body h3`
  - `ReactMarkdown` 的 `h2` / `h3` 自定义渲染器 inline style
- 计划做法：
  - 将 h2、h3 相对正文同步上调一档，保持标题层级关系不变。
  - 继续保留当前标题间距和分隔线逻辑，避免 TOC 与正文结构感被打乱。
- 目标效果：正文放大后，h2/h3 不会显得过小，整篇文章层次依旧清楚。

### 3. 视情况微调文章主标题
- 文件：[Post.tsx](file:///c:/Users/11853/Desktop/个人网站/blog/src/pages/Post.tsx)
- 修改位置：`#post-title` 的 `text-xl md:text-3xl`
- 计划做法：
  - 如果正文放大后主标题对比度不足，则同步将主标题提升一档。
  - 若实测正文放大后主标题仍足够突出，则保持现状，避免首屏过重。
- 决策原则：主标题是否增大，以与正文的视觉差是否合理为准，而不是机械同步放大。

### 4. 保持 UI 字体不变
- 文件：[index.css](file:///c:/Users/11853/Desktop/个人网站/blog/src/index.css)
- 文件：[Post.tsx](file:///c:/Users/11853/Desktop/个人网站/blog/src/pages/Post.tsx)
- 计划做法：
  - 不修改导航栏、目录、时间信息、按钮、侧边栏的 `--font-sans` 体系。
  - 确保仅文章内容区域变大，继续维持“内容传统、界面现代”的混搭策略。
- 目标效果：阅读氛围更强，但站点操作界面仍保持清爽、易扫读。

### 5. 验证并回归检查
- 计划验证页面：
  - 真实文章页：[markdown-syntax-test.md](file:///c:/Users/11853/Desktop/个人网站/blog/src/posts/markdown-syntax-test.md)
- 验证重点：
  - 正文是否明显放大一号
  - h2/h3 与正文比例是否自然
  - 列表、引用、表格、数学公式是否同步协调
  - TOC、顶部元信息、按钮、侧边栏是否仍保持无衬线风格
  - 移动端与桌面端是否出现过度换行或首屏拥挤

## Assumptions & Decisions
- 已确定不再单独做测试网页，直接基于真实文章页验证。
- 已确定继续使用当前满意的 CDN 字体方案 `LXGW WenKai Screen`，不改为本地字体文件。
- “整体放大一号”的实施方式采用“只调整文章内容区域，不扩大 UI 区域”。
- 为降低风险，优先采取最小改动方案：以 `index.css` 为主，必要时再补 `Post.tsx` 中的标题尺寸。
- h2/h3 必须双处同步（CSS + inline style），这是当前代码结构决定的硬约束。

## Verification Steps
1. 打开真实文章页，确认页面正常渲染，不再出现 `Post not found`。
2. 对比修改前后正文首屏密度，确认文章字体整体变大一号。
3. 检查 h2/h3、列表、引用、表格、公式与正文的比例关系。
4. 检查文章元信息、目录、按钮、导航是否仍保持无衬线字体。
5. 检查桌面端和较窄视口下是否出现异常换行、过大段落间距或 TOC 视觉失衡。
